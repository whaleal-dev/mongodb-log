# FTDC 内存安全与指标组查询加固计划

**目标：** 防止异常 FTDC 文件轻易触发 OOM；保持现有 Metric 操作方式和接口结构，在有界内存中按选择顺序逐组返回、逐组渲染，并隔离单组失败。

**边界：** 继续采用本地单用户模型，不增加多用户并发控制、删除与查询复杂锁、任务恢复、数据库、新依赖或新存储结构；不删除旧组件，不修改 Log 功能。

## 1．同步规范

- [x] 删除 `CLAUDE.md` 中过时的单指标查询描述。
- [x] 明确指标组是唯一产品查询方式。
- [x] 写入顺序加载、失败隔离、解码内存边界、时间断裂和极值保真降采样规则。

## 2．控制 FTDC 解码内存

- [x] 根据真实样本和 MongoDB FTDC 格式确定单 block 样本上限。
- [x] 同时限制解压字节数、样本数和「指标数 × 样本数」，并在循环及数组分配前校验。
- [x] 使用声明长度的定长缓冲区解压，避免完整 payload 二次复制。
- [x] 严格检查实际解压长度、压缩尾部数据、varint 和 RLE 数量。
- [x] 为超大规模、高压缩比、长度不一致和截断数据补充回归测试。

## 3．优化指标组读取

- [x] 索引只提取当前指标组需要的列。
- [x] 跳过无关列时不创建列级 baseline、offset 和 zero 数组。
- [x] 同一源文件的多个 block 复用一个文件通道。
- [x] 一次请求内复用索引和文件元数据，保持逐 block 流式处理。

## 4．增强顺序加载与失败隔离

- [x] 按用户选择顺序逐组请求，首组返回后立即渲染。
- [x] 单组失败显示对应错误卡片，继续请求后续组，最后统一提示失败数量。
- [x] 轮询增加轻量 `pending` 标记，禁止同一任务状态请求重叠。

## 5．修正时间断裂

- [x] 使用过滤后相邻间隔的中位数作为典型周期。
- [x] 覆盖固定周期、轻微抖动、单次长宕机、多段断裂和单采样点。
- [x] 断裂处插入 `null`，ECharts 悬浮值显示 `-` 且不跨断裂连线。

## 6．保留异常峰值和低谷

- [x] 每个时间桶保留最小值、最大值及其时间，按真实时间输出。
- [x] 保留首尾点，且最终点数不超过接口上限。
- [x] 全零判断和 `min`、`max`、`avg` 使用完整原始有效点统计。

## 7．测试与内存验证

- [x] 完成后端异常 block、选择性索引、极值降采样和失败隔离测试。
- [x] 完成前端严格顺序、即时渲染、失败隔离、轮询防重叠和断裂测试。
- [x] 运行完整 Maven 测试、完整前端测试、前端构建和 Maven 打包。
- [x] 使用受限 JVM 堆和真实 FTDC 样本连续查询核心指标组，观察堆内存。
- [x] 浏览器验证展开、折叠、全零隐藏和顺序加载。

## 8．维护进度

- [x] 仅在实现并验证成功后更新 `ROADMAP.md` 的已完成项和最近验证。

## 验收标准

- 异常 FTDC 在大规模数组分配前返回明确格式错误。
- 指标组严格按选择顺序逐个出现，失败组不阻塞后续组。
- 时间抖动不产生假断裂，真实断裂显示为 `-`。
- 降采样后仍能看到短时尖峰和低谷，完整统计口径不变。
- 完整自动测试、构建、真实样本受限堆查询和浏览器检查均通过。
