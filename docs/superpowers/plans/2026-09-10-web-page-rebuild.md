# Web 页面重做实施计划

**Goal：** 实现已确认的离线 LogVis 页面需求，并完成数据、接口、页面和可执行包验证。

**Architecture：** 保留现有流式解析与 Top 5000 存储。补齐聚合和任务时间范围，前端按独立区块展示结果，散点使用已有轻量接口，单条详情按需读取。

**Tech Stack：** Java 17、Spring Boot、Vue 3、Element Plus、ECharts；不新增依赖。

**Spec：** [Web 页面需求](../specs/2026-09-10-web-page-requirements.md) 。

## 执行约束与口径

- 用户已确认需求并授权开发，在当前工作目录继续已有改动，不覆盖其他工作，不提交或推送已有混合改动。
- 全部慢查询参与聚合，全局 Top 5000 保留原文。按用户追加要求，Top 50 各模式的最慢语句独立保留一条原文，最终只持久化 50 个模式样本。
- 源码核对：原服务的 Top 50 分组键为 Namespace、Operation、Pattern，按次数倒序；IP 按响应量倒序，Namespace 按响应量、次数倒序。
- CPU 比例为 `cpuNanos / 1000000 / durationMillis * 100`。使用原版算法 `ceil(floor(percent) / 10) * 10` 分桶，标清含义，允许超过百分之百；缺失与零值区分。
- 连接数按 UTC 小时汇总连接事件中明确记录的 connectionCount 样本，取算术平均；纳入有效零值，不复制原版排除零连接数的偏差。不填充无样本时段，页面标注非时间加权平均。
- 详情按需重新解析已经保留的原始行，提取日志 id、severity、component、context、message，不将 queryId 当作日志消息 id。
