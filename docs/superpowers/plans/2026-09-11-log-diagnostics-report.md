# MongoDB Log 运行诊断与 Markdown 报告实施计划

## 阶段 1：规范与回归基线

- 更新 `CLAUDE.md`、设计规格和 `ROADMAP.md`。
- 固定现有 summary、接口和前端结果页回归测试。
- 为 4.4、5.x、6.x、7.x、8.x 准备最小结构化日志夹具。

## 阶段 2：诊断解析与有界聚合

- 先写事件分类、字段覆盖、连接、客户端、复制集和慢查询效率失败测试。
- 增加独立 `analysis/diagnostics` 模型和聚合器。
- 保持现有 `ParsedLogEntry` 语义；仅增加诊断所需的可选信封元数据。
- 使用稳定事件键、固定 Top 容量、最多 3 条脱敏样本和最多 2,000 个时间桶。

## 阶段 3：独立存储与接口

- 先写 `diagnostics.json` 原子保存、历史任务缺失及删除联动测试。
- 扩展任务仓库和执行器，在 summary 之外发布诊断文件。
- 增加 `/diagnostics`，保持 `/summary` 完全兼容。

## 阶段 4：运行诊断页面

- 先写按需加载、历史任务、请求竞态和数字核对测试。
- 新增运行诊断页签及异常、连接、复制集、慢查询效率、数据质量组件。
- 保留旧慢查询组件，不搬迁内部状态和布局 key。

## 阶段 5：Markdown 报告

- 先写报告内容、转义、脱敏、历史任务及响应头失败测试。
- 使用标准库实现确定性 Markdown 生成，不增加依赖。
- 增加 Web 下载按钮和下载失败提示。

## 阶段 6：真实数据与发布验证

- 使用两份真实 MongoDB 日志全量验证。
- 对比改动前后的慢查询数、耗时分布、Top 统计和连接均值。
- 复算异常、连接、客户端、复制集和慢查询效率关键结果。
- 验证导出文件脱敏、可读且能被常见 Markdown 工具解析。
- 运行后端、前端、构建、JAR 和浏览器端到端测试。
- 只把已验证事项写入 `ROADMAP.md` 已完成并提交功能分支。
