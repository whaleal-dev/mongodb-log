# Web 页面需求：离线 LogVis

日期：2026-09-10。

状态：已实现并通过自动化测试、打包及浏览器验收；包含开发中追加的图表切换、右侧解读、独立样本、布局记忆和删除要求。

## 1．范围与优先级

本工具面向本地上传 MongoDB 日志的离线分析。任务列表与分析结果页应按原 `LogVis` 的区块顺序和展示方式重做，不继续沿用当前的“摘要卡片＋维度切换＋慢查询列表”结构。

本文是 Web 页面展示、交互及相关数据口径的最新依据。与原设计规格、原实施计划中的页面描述冲突时，以本文为准；其余解析、离线运行、数据保留和安全约束继续遵循项目规范。

用户已授权按本文开发；开发中追加的展示与样本保留规则已合并到本文。

## 2．任务列表页

原版包含 `Task Name`、`Status`、`Create Time`、`Time Range`，以及 `Analyse`、`Event Log`、`Delete` 操作。离线版展示以下列：

| 列 | 内容 |
|---|---|
| 任务名称 | 上传分析任务的名称 |
| 状态 | 当前任务状态 |
| 创建时间 | 任务创建时间 |
| 上传文件 | 本任务上传的文件；支持一个任务包含多个文件 |
| 文件大小 | 本任务上传文件的总大小 |
| 日志时间范围 | 日志覆盖的起止时间 |
| 操作 | 查看分析结果 |

集群选择、节点选择、`Event Log` 不照搬。按用户追加要求，操作列增加本地任务删除：确认后清理任务元数据、聚合结果、Top 5000、独立样本及残留上传副本，保留用户原始文件和其他任务。排队中／分析中的任务暂不允许删除，避免与后台写入冲突。

## 3．分析结果页

按下表顺序展示，保留各区块独立的表格或图表形式：

| 顺序 | 区块 | 展示方式 | 展示内容 |
|---|---|---|---|
| 1 | 任务信息 | 信息栏 | 任务名、文件、大小、状态、日志时间范围 |
| 2 | Failed Operations | 小表格 | HeartBeat Failed |
| 3 | Stats by IP Top 20 | 小表格 | IP、慢查询数、响应数据量 |
| 4 | Operations Stats | 小表格 | Operation、数量 |
| 5 | Stats by Namespace Top 20 | 小表格 | Namespace、数量、响应数据量 |
| 6 | 慢查询耗时区间分布 | 柱状图／精确数据表切换 | 各耗时区间的数量、占比和平均耗时 |
| 7 | Statistical Information Top 50 | 全宽表格 | Namespace、Operation、Pattern、Plan Summary、CPU、次数、总耗时、平均、最大、最小、最慢语句 |
| 8 | Operation Counts | 饼图 | 各 Operation 数量 |
| 9 | Response Length by Namespace | 饼图 | 各 Namespace 响应数据量 |
| 10 | Plan Summary | 饼图 | COLLSCAN、IXSCAN 等执行计划数量 |
| 11 | CPU Cost by Namespace and Operation | 饼图 | Namespace 与 Operation 维度的 CPU 占比，日志存在 `cpuNanos` 时展示 |
| 12 | CPU Cost by Operation | 标签页＋饼图 | 按 insert、update、delete、find 展示 CPU 区间，日志存在 `cpuNanos` 时展示 |
| 13 | Average Connections | 折线图 | 按小时统计平均连接数，能够解析连接事件时展示 |
| 14 | Slow Query Information Top 5000 | 散点图＋单条详情 | 时间、耗时、Namespace、queryId；点击后加载完整日志 |

Top 50 按出现次数倒序，保持原聚合策略，并在界面明确标注排序依据，不改成按总耗时排序。聚合结果基于全部相关日志，不以 Top 5000 明细代替统计样本。

开发后追加：Top 50 的入选范围仍按次数确定，页面支持点击集合、操作、模式、计划和数值列的表头，在这 50 组内切换升降序。默认次数降序；首次选择其他列为升序，重复点击反转；缺失值始终置后，显示排序方向。最慢语句为操作入口，不参与排序。

页面专业化以清晰读数为目标：紧凑工具栏、明确标题层级、低饱和配色、数值右对齐、统一边框和较少装饰；说明主要放在问号帮助中，保留必要的统计口径与异常提示。

结果页显示解析质量提示（失败、部分解析、跳过行数及原因分类），以免空结果被误读。任务轮询禁止同一任务请求重叠，旧任务／旧列表响应不得覆盖当前状态。散点窗口高度不低于 420px，其他统计图设置相应最小高度，保证可读与可点击。

### 最慢语句与详情解读（开发中追加）

- Top 50 每个模式独立保留该组耗时最长的一条原始日志，即使该日志未进入全局 Top 5000，也必须可查看；相同耗时按时间、文件序号、行号确定样本。
- 样本随模式统计持久化，不通过 Top 5000 明细接口查询。历史任务未保存样本时明确提示重新上传，不能以全局最慢日志代替。
- 散点详情使用右侧抽屉；模式最慢语句也在右侧展示该样本原文与已记录字段。
- 二次解读包含集合与操作、耗时与 CPU 耗时比例、执行计划、文档／索引扫描量与返回量、响应大小、等待与磁盘读取等实际可获得字段。区分事实、线索和排查建议；缺失字段不推断为零，不仅凭 COLLSCAN 或耗时断言根因。
- 所有解读在本机根据日志字段生成，不引入在线 AI 或外部日志上传。

图表须提供精确数据表或可核对数值；字节、耗时和 CPU 单位应明确。时间沿用项目规范：存储为 UTC Epoch Milliseconds，按本机时区展示。

### 3.1 本轮追加的展示要求

用户在开发过程中明确追加以下要求，优先于本文此前“图下同时保留数据表”的布局描述：

- 耗时分布、各饼图和连接折线图默认显示图表，通过“图表／数据表”切换查看精确数值，同一区块不同时展开图和表。
- 原本只有表格的统计区块继续使用表格，不额外添加重复图表；Top 5000 仍使用散点图与当前一条详情，不引入慢查询列表。
- 指标改用易读的中文名称，并在名称后放置问号图标，解释含义、单位、统计范围、排序依据及缺失数据口径。
- 优化整体排版：统一卡片、标题层级、留白、表格密度、颜色和响应式布局，避免信息重复与过长页面。
- 小数指标统一四舍五入到 3 位小数，计数与原始日志字段保持原值。小数格式适用于表格、标签、Tooltip 和详情解读，不改变后端聚合精度。
- 各指标面板可从右下角拖动调整宽高，布局自动保存在本机浏览器，下次打开默认恢复；窄窗口限制面板宽度，避免溢出。提供恢复默认布局入口。
- 数据库术语保留原文，心跳失败项显示 `HeartBeat Failed`；中文说明仍保留在指标帮助中。
- 查询模式过长时单行省略，悬浮或键盘聚焦展示可换行的完整内容。
- 图表原名与中文名对应：Failed Operations → 失败操作；Stats by IP Top 20 → 客户端统计 · Top 20；Operations Stats → 操作类型统计；Stats by Namespace Top 20 → 集合统计 · Top 20；Statistical Information Top 50 → 查询模式统计 · Top 50；Operation Counts → 操作类型占比；Response Length by Namespace → 集合响应量占比；Plan Summary → 执行计划分布；CPU Cost by Namespace and Operation → CPU 耗时占比；CPU Cost by Operation → CPU 耗时比例分布；Average Connections → 每小时平均连接数；Slow Query Information Top 5000 → 最慢查询时间分布 · Top 5000。

## 4．Top 5000 慢查询交互与数据约定

1. 从全部慢查询按耗时倒序选取最慢 Top 5000；不足 5000 条时保留全部慢查询。耗时相同的选择顺序沿用原设计规格。
2. 后端返回绘图所需的轻量数据：`timestamp`、`durationMillis`、`queryId`、`namespace`，不在绘图响应中批量返回完整日志。
3. 散点图横轴为日志时间，纵轴为耗时，单位为 `ms`。
4. 每个 Namespace 是一个散点系列，通过图例区分；不得按 Operation 分系列。
5. 支持框选缩放、时间段放大和缩放恢复。
6. 点击散点时，用该点的 `queryId` 单独请求完整日志。
7. 点击散点后从右侧打开详情抽屉，展示当前选中的一条日志；切换散点更新抽屉，不展示 Top 5000 列表。抽屉包含原始字段、attributes、原始日志及中文二次解读。
8. 单条详情包含 `id`、`timestamp`、`severity`、`component`、`context`、`message`、`attributes` 和原始日志。

原后端按 `queries.ns` 分组，散点数据结构为 `[时间, 耗时, 日志 ID]`。新工具的 `queryId` 用于定位明细，详情中的 `id` 字段需按原日志含义展示，不能仅因名称相近就混用。

本需求约定数据职责与交互，不在本轮指定新增接口路径。开发时复用或调整现有接口，保证散点轻量加载、详情按需请求，不照搬无效循环分页。

## 5．慢查询耗时区间分布

这是新工具额外增加的核心区块，原 LogVis 没有。统计范围必须为全部慢查询，不能只统计 Top 5000。

| 展示区间 | 毫秒边界 |
|---|---|
| `<100ms` | `x < 100` |
| `100–500ms` | `100 <= x < 500` |
| `500ms–1s` | `500 <= x < 1000` |
| `1–3s` | `1000 <= x < 3000` |
| `3–10s` | `3000 <= x < 10000` |
| `10–30s` | `10000 <= x < 30000` |
| `30–60s` | `30000 <= x < 60000` |
| `≥60s` | `x >= 60000` |

默认使用柱状图展示数量和占比。Tooltip 展示数量、占全部慢查询的比例和平均耗时。通过“数据表”切换查看这些精确数值，不与图表同时展示。无慢查询时，比例与平均耗时沿用原设计规格显示为零。

## 6．原版问题与离线边界

- 原版为 Top 50000，新工具使用 Top 5000。
- 原版前端存在循环分页，但后端从第二页开始返回空数据，实际只有一次有效请求；不复制该行为。
- 原版 `Accepted Connections` 饼图使用的是 IP 聚合后的响应数据量，标题与数据含义不符；新工具不保留该错误图表。
- Namespace 的 `IndexStats` 来自实时连接 MongoDB 查询集合索引。离线日志无法准确提供，缺失时明确显示“日志无法提供”，不伪造数据。
- CPU 图只在日志实际包含 `cpuNanos` 时展示；缺失时提示“日志未提供 cpuNanos”，不以零值假装存在数据。
- `Average Connections` 只在日志能解析连接事件时展示折线图，否则明确显示无数据。
- Top 50 按出现次数倒序，不按总耗时排序。

## 8．已核对的计算细节

- CPU 比例为 `cpuNanos / 1000000 / durationMillis * 100`，沿用原算法 `ceil(floor(percent) / 10) * 10`。桶 0 为 `[0,1)%`，桶 10 为 `[1,11)%`，依次递增，允许超过 100%；耗时为零不计算比例，CPU 缺失与零值分开处理。
- 连接数按 UTC 小时对明确记录的 connectionCount 取样本算术平均，包含零值。无事件小时不补零，折线留断点，非时间加权平均。
- IP 与 Namespace Top 20 按响应数据量倒序、次数倒序；Top 50 按 Namespace、Operation、Pattern 分组，按次数倒序。
- 详情字段解释核对了 [MongoDB 官方字段说明](https://www.mongodb.com/docs/manual/reference/database-profiler/) ，覆盖 CPU、扫描量、响应量、磁盘读取和锁等待的单位及含义。
