# MongoDB Log Analyzer 设计规格

> 2026-09-10 页面需求更新：Web 展示、交互及相关数据口径以 [Web 页面需求](2026-09-10-web-page-requirements.md) 为准。该需求已记录，页面重做尚待开发与验收。

## 1．目标

构建一个供运维人员在个人电脑上离线使用的 MongoDB 日志分析工具。用户双击启动后，通过本地浏览器上传一个或多个 MongoDB 日志文件。程序解析整个任务的全部日志，精确生成统计结果，永久保存按耗时排序的 Top 5000 条慢查询明细，以及 Top 50 模式各自最慢的一条独立日志样本。

## 2．非目标

- 不连接或管理 MongoDB 集群。
- 不依赖 MongoDB 服务、对象存储、配置中心、采集 Agent、容器平台或云服务。
- 不提供账号、角色、权限、远程访问和多人协作。
- 不永久保存上传的原始日志文件。
- 不保存普通日志原文；慢查询原文仅保留全局 Top 5000 与 Top 50 模式各自最慢样本。
- 不实现任意 SQL、任意查询或通用日志搜索平台。

## 3．运行方式

- 应用默认监听 `127.0.0.1:18080`。
- macOS 使用 `start.command`，Linux 使用 `start.sh`，Windows 使用 `start.bat`。
- 启动成功后自动打开 `http://127.0.0.1:18080`。
- 运行时只需要 Java 17；前端资源已包含在 JAR 中。
- 发布包后续可用 `jpackage` 生成自带 Java 运行时的各平台版本；首版交付 JAR 和三个启动脚本。

## 4．输入与任务

### 4.1 支持格式

- UTF-8 纯文本 MongoDB 日志：`.log`、`.txt` 或无扩展名。
- GZip 压缩日志：`.gz`。
- MongoDB 结构化 Extended JSON 日志。
- MongoDB 旧版单行文本日志。
- 一个任务允许上传多个轮转文件，并按用户选择顺序处理。

### 4.2 任务状态

任务状态包括 `QUEUED`、`RUNNING`、`COMPLETED` 和 `FAILED`。任务元数据记录名称、文件名、总字节数、已处理字节数、总行数、成功行数、部分解析行数、跳过行数、失败行数、慢查询数、创建时间、开始时间、结束时间和错误信息。

上传文件先复制到应用创建的临时工作目录。后台单线程依次处理任务，避免多个大文件同时争用磁盘和内存。任务完成或失败后，只删除应用创建的临时副本，不触碰用户原始文件。

## 5．解析架构

### 5.1 统一结果

解析器输出 `ParseOutcome`，包含 `ParseStatus`、可选的 `ParsedLogEntry` 和错误分类。状态定义：

- `SUCCESS`：目标字段完整解析。
- `PARTIAL`：日志主体识别成功，但一个或多个可选或派生字段失败。
- `SKIPPED`：空行或非 MongoDB 日志行。
- `FAILED`：看起来是 MongoDB 日志，但基础格式损坏，无法获得时间等核心字段。

### 5.2 格式识别

格式识别先移除 UTF-8 BOM 和首尾空白。以 `{` 开头的行先尝试 Extended JSON 解析；成功则走结构化解析器，失败后只有在行首符合旧版 ISO 时间戳时才回退到旧版解析器。禁止依赖 `{"t":{"` 这样的固定字符串前缀。

### 5.3 结构化解析器

解析字段包括：

- 时间 `t.$date`。
- 严重级别 `s`。
- 组件 `c`。
- 消息 ID `id`。
- 上下文 `ctx`。
- 消息 `msg`。
- 属性 `attr`。
- 慢查询的 `ns`、`type`、`command`、`originatingCommand`、`durationMillis`、`cpuNanos`、`reslen`、`planSummary` 和 `remote`。

仅当 `msg` 等于 `Slow query` 或存在明确的慢操作耗时字段时，记录为慢查询。查询模式按操作类型提取，并将具体值替换为类型无关占位值，生成键顺序稳定的规范 JSON。

### 5.4 旧版解析器

基础字段由时间戳、严重级别、组件、上下文和消息五段组成。命令文档提取必须使用感知字符串与转义符的括号扫描器，不能简单统计所有大括号。支持 `find`、`aggregate`、`insert`、`update`、`remove`、`getMore`、`findAndModify` 和 `createIndexes`。

旧版文本中的 BSON 扩展表达式允许在无法完整转为 JSON 时降级提取 namespace、operation、durationMillis、planSummary 和原始查询片段，并将状态标记为 `PARTIAL`，不能丢弃整行。

## 6．Top 5000

所有慢查询进入容量固定为 5000 的最小堆。比较顺序为：

1. `durationMillis` 越大越优先保留。
2. 耗时相同时，时间戳越早越优先保留。
3. 时间戳相同时，文件序号和行号越小越优先保留。

堆内最差元素位于顶部。容量未满时直接加入；容量已满且新元素更优时替换顶部。任务结束后按最终展示顺序排序并写入 JSONL。该算法空间复杂度为 `O(5000)`，结果必须通过超过 5000 条和相同耗时边界测试。

## 7．精确聚合

聚合基于全部解析日志流式计算，不依赖 Top 5000：

- 总日志和解析质量统计。
- 全部慢查询数量和总耗时。
- 按 operation 统计数量和总耗时。
- 按 namespace 统计数量、总响应量和总耗时，展示 Top 20。
- 按 query pattern 统计数量、总耗时、平均值、最大值、最小值、CPU 总耗时、执行计划和最慢样例，展示 Top 50。
- 按 planSummary 统计数量，展示 Top 10。
- 按 remote IP 统计慢查询数量和响应量，展示 Top 20。
- 按 operation＋namespace 统计 CPU 占比；只有出现 `cpuNanos` 时返回 CPU 可用。
- 心跳失败计数。

高基数字段通过内存 Map 聚合。每个任务一次只处理一个线程；如果未来真实数据证明查询模式基数造成内存压力，再引入分段归并，不在首版预先复杂化。

## 8．耗时区间分布

耗时区间固定为：

| key | 范围 |
|---|---|
| `lt_100ms` | `< 100ms` |
| `100ms_500ms` | `100ms <= x < 500ms` |
| `500ms_1s` | `500ms <= x < 1000ms` |
| `1s_3s` | `1000ms <= x < 3000ms` |
| `3s_10s` | `3000ms <= x < 10000ms` |
| `10s_30s` | `10000ms <= x < 30000ms` |
| `30s_60s` | `30000ms <= x < 60000ms` |
| `gte_60s` | `>= 60000ms` |

每个区间记录数量、占全部慢查询比例、总耗时、平均耗时和最大耗时。边界按左闭右开处理，百分比由最终总数计算。没有慢查询时所有百分比和平均值均为零。

## 9．持久化

应用数据目录结构：

```text
data/
├── tasks-index.json
├── tasks/<task-id>/metadata.json
├── tasks/<task-id>/summary.json
├── tasks/<task-id>/top-slow-queries.jsonl
└── work/<task-id>/uploaded-files
```

结果先写同目录临时文件，再通过原子移动替换目标文件，避免进程中断留下半份结果。启动时扫描任务索引；遗留的 `RUNNING` 任务标记为 `FAILED`，错误原因写为“应用在分析过程中退出”。

## 10．HTTP API

- `POST /api/tasks`：multipart 上传，参数 `name` 和多个 `files`，返回任务 ID。
- `GET /api/tasks`：按创建时间倒序返回任务列表。
- `GET /api/tasks/{taskId}`：返回任务状态和进度。
- `GET /api/tasks/{taskId}/summary`：返回完成任务的聚合结果。
- `GET /api/tasks/{taskId}/slow-queries`：原设计为 Top 5000 分页、排序和过滤接口；新版页面需要轻量散点数据，具体接口调整在后续开发中确定，不再以分页列表作为页面交互。
- `GET /api/tasks/{taskId}/slow-queries/{queryId}`：返回单条完整明细。

上传校验拒绝空文件、超过配置上限的请求和不支持的压缩格式。API 错误使用统一 JSON 结构：`code`、`message` 和可选 `details`。

## 11．前端

前端使用 Vue 3，页面按 [Web 页面需求](2026-09-10-web-page-requirements.md) 重做：

- 保留任务名称、多文件上传和开始分析能力。
- 任务列表展示任务名称、状态、创建时间、上传文件、文件大小、日志时间范围和查看分析结果操作。
- 结果页按最新需求的区块顺序展示小表格、耗时分布、全宽 Top 50 表格、饼图、条件展示的 CPU 与连接分析。
- 耗时区间分布基于全部慢查询，柱状图与精确表格切换展示；其他统计图采用相同切换方式。
- Top 50 按出现次数倒序，并明确标注排序依据；各模式独立保留最慢的一条原文，不依赖 Top 5000。
- Top 5000 使用按 Namespace 分组的散点图，支持缩放；点击散点后按 `queryId` 加载单条完整详情，在右侧抽屉展示字段、原文与解读。
- 不再使用摘要卡片＋维度切换＋慢查询列表作为结果页结构。

图表空数据必须显示原因；CPU 无数据时显示“日志未提供 cpuNanos”。所有字节和毫秒单位明确标注。图表只展示汇总，精确数值可在表格或 tooltip 中核对。

## 12．安全与隐私

- 仅监听本机回环地址。
- 文件名只保留基础名称，拒绝路径穿越。
- 不执行日志中的任何内容。
- 原始上传临时副本在任务结束后清理。
- 页面渲染原始日志时按纯文本处理，禁止注入 HTML。
- 日志、IP 和查询内容不发送到任何外部地址。

## 13．验证标准

- 解析器单元测试覆盖结构化、旧版、GZip、BOM、空行、异常行和支持的八类操作。
- Top 5000 和八个耗时区间都有精确边界测试。
- 聚合结果使用手工可复算数据集验证。
- 文件存储使用临时目录集成测试，验证原子写入和重启恢复。
- MockMvc 集成测试完成上传到结果查询的闭环。
- 前端测试覆盖耗时格式化、进度展示、空数据和 API 错误提示。
- `mvn test`、`npm test`、`npm run build` 和 `mvn package` 全部通过。
- 启动 JAR 后，通过浏览器上传结构化和旧版样例，核对任务进度、耗时分布、Top 5000 和明细。
