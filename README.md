# MongoDB Log & Metric Analyzer

供运维人员在个人电脑上离线使用的 MongoDB 日志与 FTDC 指标分析工具。双击启动后，可在页面顶部切换 MongoDB Log 和 MongoDB Metric 工作区。

面向使用者的完整操作步骤、数据保留方式和能力边界见 [使用方法与限制](docs/user-guide.md)；运行后也可点击页面右上角的「使用说明」。

## 核心能力

- 支持 MongoDB 4.2 及之后的结构化 Extended JSON 日志。
- 支持 MongoDB 旧版单行文本日志。
- 支持普通文本文件和 `.gz` 压缩文件，一次可上传多个文件组成一个任务。
- 支持一次上传最多 20 个 `diagnostic.data/metrics.*` FTDC 文件，按内容识别，不要求固定扩展名。
- FTDC 按指标组查询，组内多指标支持合并展示／分开展示、全零指标一键隐藏、时间断点和纵向折叠。
- 基于全部慢查询精确统计八个耗时区间，不使用 Top 5000 抽样。
- 永久保存全局最慢 Top 5000 明细，以及 Top 50 查询模式各自最慢的一条独立样本，其余日志只参与聚合。
- 展示失败操作、操作类型、集合、查询模式、执行计划、客户端 IP、CPU、响应量和小时连接数。
- 提供独立的运行诊断页，汇总异常时间线、连接与客户端、复制集／网络事件、慢查询效率线索和 MongoDB 4.4＋字段覆盖。
- 支持从结果页一键导出脱敏 Markdown 报告，方便交给 AI 进行二次分析。
- 统计图支持“图表／数据表”切换，指标旁的问号说明含义与统计口径。
- 耗时、均值和占比等小数四舍五入到 3 位；计数和原始日志保持原值。
- 拖动各指标窗口右下角调整宽高，尺寸保存在本机浏览器，下次打开自动恢复；可恢复默认布局。
- 按集合分组的慢查询散点支持框选、时间缩放与恢复；点击后从右侧查看完整日志和字段解读。
- 仅监听 `127.0.0.1:18080`，日志和 FTDC 数据不会上传到外部服务。

## 一键启动

发布包目录必须包含：

```text
mongodb-log-analyzer/
├── mongodb-log-analyzer.jar
└── scripts/
    ├── start.command
    ├── start.sh
    └── start.bat
```

- macOS：首次使用可在终端执行 `chmod +x scripts/start.command scripts/start.sh`，之后双击 `scripts/start.command`。
- Linux：执行 `./scripts/start.sh`。
- Windows：双击 `scripts\start.bat`。

运行要求是 Java 17 或更高版本。启动脚本使用 `-Xms128m -Xmx2g`，其中 `-Xmx2g` 只限制 Java 堆；整个进程还会使用少量元空间和原生内存。启动成功后会自动打开 `http://127.0.0.1:18080`。如果浏览器没有自动打开，可以手动访问该地址。

停止程序时，关闭启动窗口或按 `Ctrl+C`。

## 数据与隐私

应用默认在启动目录的 `data` 下保存任务：

```text
data/
├── tasks-index.json
├── tasks/<task-id>/metadata.json
├── tasks/<task-id>/summary.json
├── tasks/<task-id>/diagnostics.json
├── tasks/<task-id>/top-slow-queries.jsonl
├── work/<task-id>/
└── ftdc/
    ├── tasks-index.json
    ├── tasks/<task-id>/
    │   ├── metadata.json
    │   ├── catalog.json
    │   ├── blocks.idx
    │   └── source/<uploaded-file>
    └── work/<task-id>/
```

应用不会修改用户选择的原始文件。普通日志上传副本只在分析期间保存在 `work`，完成或失败后删除；慢查询仅保留全局 Top 5000 和 Top 50 模式各自最慢的独立样本。FTDC 为支持后续按指标查询，会在任务目录保留上传副本、指标目录和紧凑二进制索引，但不会保存全量展开后的时间序列。删除 FTDC 任务只清理应用保存的副本和索引，不会删除用户原文件。所有解析与解读均在本地完成，不调用外部 AI 服务。

## 查看 FTDC 指标

在页面顶部选择「MongoDB Metric」，上传 1～20 个 FTDC 文件并等待索引完成。任务页展示文件大小、Block 数、指标数、原始样本点数和时间范围。

进入任务后，一次选择并查询一个指标组。组内全部指标可合并在一个 ECharts 中，也可逐指标分开展示；页面根据当前数据的最小值、最大值和平均值识别全零指标，并支持一键隐藏或恢复。相邻时间差明显超过主要采样间隔时，折线在该处断开，空值在提示中显示为 `-`，便于定位停机或采集异常。

分组规则按指标父路径生成，并兼容 WiredTiger cache／capacity／transaction 和 netstat 的特殊路径。分组查询同一 Block 只解压一次，单组最多 200 个指标、每指标最多返回 1,200 点。产品不提供单指标查询、原始值分页或完整指标导出，避免一次渲染或物化无界数据。

## 查看分析结果

任务列表选择“查看分析结果”。耗时分布统计全部慢查询；查询模式按出现次数排序；散点只展示全局最慢 5000 条。

统计区块默认显示图表，点击“数据表”查看精确数值；点击指标名后的问号了解范围、单位及排序依据。点击散点，右侧详情依次展示字段解读、排查线索、命令、日志记录、属性与原文。“最慢语句”直接展示对应模式的独立最慢样本，不受散点保留范围限制。

查询模式过长时会省略显示，悬浮或键盘聚焦后展示完整内容。指标窗口的宽高布局按指标保存在当前浏览器；更换浏览器或清除站点数据后需重新设置。

Top 50 默认按出现次数降序。点击具体表头可切换升降序，数值按实际值比较，缺失值始终置后。排序只改变已入选的 50 组的展示顺序，不改变后端按次数选取 Top 50 的范围。

结果页默认进入原有“慢查询分析”。点击“运行诊断”后，页面按需加载异常日志、连接 churn、认证情况、客户端应用／Driver、复制集和网络事件、慢查询效率线索，以及 MongoDB 4.4＋结构化日志字段覆盖。分析按字段是否存在判断能力，不要求提前知道精确版本；缺失字段显示为无数据，不按零值处理。

点击“导出 AI 分析报告”会下载当前任务的 Markdown 报告。报告按“慢查询分析”和“运行诊断”两个页面区块导出相关数据，包含完整聚合、耗时分布、Top 20、Top 50、脱敏 Top 5000、CPU、连接时间序列、异常时间桶、复制集事件、效率线索和字段覆盖；不包含完整原始日志、命令字面值、用户名或完整客户端 IP。导出在本地完成，不会自动把报告发送给任何 AI 服务。历史任务没有 `diagnostics.json` 时仍可使用旧页面并导出降级报告，诊断部分会提示重新上传。

结果页会提示解析失败、部分解析和跳过的行数，可展开查看分类。此类任务的统计仅包含有效提取字段。更新版本不会重算历史结果，需要重新上传原日志才能应用新的解析修正。

任务列表点击“删除”，确认后清理该任务的元数据、聚合结果、慢查询原文、独立样本及残留上传副本。用户原始日志和其他任务不受影响。排队和分析中的任务需等结束后再删除；清理失败会保留任务记录，可在解决权限等问题后重试。

历史任务缺少新版统计或独立样本时，页面会明确提示重新上传原日志分析，程序不会伪造缺失结果。

## 耗时区间

固定区间为：`<100ms`、`100ms-500ms`、`500ms-1s`、`1s-3s`、`3s-10s`、`10s-30s`、`30s-60s`、`>=60s`。边界采用左闭右开，分布统计覆盖任务中的全部慢查询。

## 本地构建

需要 Java 17、Maven、Node.js 和 npm：

```bash
mvn clean test
cd web
npm test -- --run
cd ..
mvn package
```

`mvn package` 会安装锁定的前端依赖、构建 Vue 页面并生成 `target/mongodb-log-analyzer.jar`。项目目录中的启动脚本能直接找到该文件；制作给运维人员的目录时，把 JAR 复制到项目根层并保留 `scripts` 目录即可。最终运行不需要 Node.js、MongoDB、Nacos、S3 或网络连接。

## 常见问题

- 提示 Java 版本过低：安装 Java 17 或更高版本，并确保 `java -version` 指向新版本。
- 端口被占用：关闭占用 `18080` 端口的程序后重试。
- `.gz` 分析失败：确认文件确实是 GZip 压缩格式，而不是仅修改了扩展名。
- CPU 图表无数据：日志本身没有 `cpuNanos` 字段，页面会明确提示。
- 页面长时间显示排队：工具使用单工作线程，前一个大任务完成后会自动开始下一个任务。
- MongoDB Metric 长时间显示排队：FTDC 建索引和指标组查询共用一个公平串行通道；等待当前重型操作结束后会自动继续。
- FTDC 文件无法解析：工具按内容验证 MongoDB FTDC 格式；文件截断、压缩数据损坏或不含指标 Block 都会明确标记任务失败。
- FTDC 数据占用磁盘：任务会保留上传副本和二进制索引；请在 FTDC 任务列表删除不再需要的任务，用户原文件不受影响。
- 内存上限已提高但查询仍保持有界：`-Xmx2g` 是安全上限，不代表程序会主动使用更多内存；一次只查询一个指标组，同一 Block 一次恢复最多 200 个组内指标。
- 应用在排队或分析期间退出：重启后中断任务会标记失败，可删除该任务后重新上传；不会继续使用不完整副本生成报告。
